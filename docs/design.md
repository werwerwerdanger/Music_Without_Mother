# 设计说明

这份文档解释三件事：**参数从哪来**、**为什么这么设计**、**哪些是妥协**。

答辩时被问「为什么是 +9dB 不是 +12dB」这类问题，答案在这里。

## 一、参数来源

所有风格参数都来自对六首同流派样本的实测，不是凭空设定。

### 通透风格

| 参数 | 值 | 依据 |
|---|---|---|
| 低频增益 | +9 dB | 实测 sub(20-120Hz) 占 42-53%，正常歌 20-30% |
| 高频衰减 | -18 dB | 实测 hi(4k+) 占 2-4%，正常歌 8-15% |
| 鼓型 | 48Hz 正弦，每拍 | 实测 kick 密度 0.32-1.69/s |
| 混响 | 15% | 实测动态范围 80-174dB，压缩感强，空间少 |
| 怪叫 | 段落处插入 | 实测怪叫出现在能量峰值的孤立点，不按拍点 |

**为什么是 +9 而不是 +12**：+12 会让低频完全盖住中频，测出来的样本虽然低频重，但中频（300-1000Hz）仍占 14-22%，不是全被吃掉。+9 能到这个比例。

### 古典风格

| 参数 | 值 | 依据 |
|---|---|---|
| 速度 | ×0.6 | 古典 Adagio 66-76 BPM，原曲通常 120-160 |
| 鼓型 | 定音鼓，每 4 下取 1 | 古典编制里打击乐是强调用，不是铺底 |
| 混响 | 55% | 音乐厅混响时间 1.5-2.5s |
| EQ | 平直 | 古典不强调低频，追求平衡 |

### 8-bit 风格

| 参数 | 值 | 依据 |
|---|---|---|
| 位深 | 4 bit | 街机音源（NES/GameBoy）通常 4-7 bit |
| 降采样 | 4 倍 | NES 采样率 1.79MHz/分频后约 11kHz |
| 鼓型 | 噪声脉冲 + 方波 | 硬件只有方波/三角波/噪声三个通道 |
| 混响 | 2% | 硬件没有混响 |

## 二、为什么这么设计

### 1. 不做 MIDI 中转

```
❌ 音频 → MIDI → 改 → 渲染
   问题：MIDI 转录有损，滑音、颤音、时值微差全丢

✅ 音频 → 结构分析（拍点/和弦/能量）→ 重写伴奏 → 混音
   保留原始人声的全部细节
```

**MIDI 是音符的抽象，音频是声音的全部。往抽象走一步，就丢一层信息。**

转换只需要结构信息（拍点、和弦、段落），这些从音频直接分析比转 MIDI 更准。

### 2. 鼓点是「重写」不是「转换」

```
原鼓 → EQ → 新鼓     ❌ 做不到，鼓的音色和节奏是一体的
原鼓丢弃 → 按风格生成新鼓  ✅
```

鼓点检测只用来确定**位置**（where），节奏型和音色完全重新生成（what）。

这也是为什么「8-bit 风格」能成立——街机根本没有真实鼓组，只能合成。

### 3. 怪叫让用户标注，不做自动检测

```
自动检测段落边界  →  准确率低（段落是语义标签，不是声学特征）
用户点击标注      →  100% 准确，且交互成本低
```

**人机分工**：算法找位置，人定语义。

怪叫在样本里出现在「能量峰值的孤立点」，不是固定在拍点或小节某处。这种位置靠算法猜不准，但用户听一遍就知道该放哪。

### 4. 音色自己合成，不依赖 SF2

```
SF2 采样      参数固定，弦乐的起音和颤音改不了
程序化合成    每个参数可控
```

弦乐的三个关键要素：

```python
慢起音      0.1-0.2s（弓压上弦需要时间）
颤音        0.4% 深度，5.5 Hz
失谐双层    0.25% 频率差，模拟多人合奏
```

**SF2 采样给不了这三个**——它的 Strings 起音是录死的。

合成方式：

```
soft_saw(freq, t) = Σ sin(2π·k·f·t) / k^1.8   k=1..10
                 → 谐波比纯锯齿衰减快，比正弦丰富，接近弦乐
```

## 三、已知局限

### 1. 节拍对齐

变速用 `librosa.time_stretch`，会对整首音频做时间拉伸。**如果原曲有速度变化，变速后可能和标注重音不符。**

### 2. 鼓点检测的假阳性

人声的爆破音（「哈」「崩」）在频谱上和军鼓高度重叠，会被误判为鼓点。

实测数据：样本的 drums 轨里 73.8% 是低频，军鼓只剩 1.5%，说明分离阶段就已经混淆。

**这是物理限制，任何模型都无法完全解决。**

### 3. 音色上限

程序化合成能调参数，但**比不过真实采样**（商业音源库有上千个采样层）。当前实现是「可控但不够真」。

### 4. 和声重写没实现

目前的伴奏重写是**按固定和弦进行生成**（F#-D#m-B-C# 等），不分析原曲和弦。

如果要真正「保持原曲和声换风格」，需要加一步 chroma 分析和弦提取。这是下一步。
